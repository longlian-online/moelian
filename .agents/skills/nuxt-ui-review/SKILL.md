# Nuxt UI Review

审查 UI 重写中的行为回归、组件复用、样式归属、composable 边界与 SSR 一致性。默认只审查，输出有证据的结论；修复遵循用户另行授权的范围。

## 确定审查范围

- 阅读仓库及目标子目录 AGENTS.md、package.json、锁文件、Nuxt 配置、布局、插件和相关测试。依据实际安装版本判断 API，不把最新 Nuxt 文档直接套到旧版本。
- 检查工作区改动和近期 UI 提交，确定比较基线；不能把 HEAD 的空 diff 当成“没有问题”。若重写起点无法确定，明确当前快照审查范围，并标记无法归因的既有问题。
- 阅读目标文件、调用方和相邻实现，追踪页面 → 组件 → composable/store → API 数据流。保留已有修改，不为了 review 进行自动格式化或重构。

## 组件与样式复用

| 观察到的重复 | 判断与抽取方向 |
| --- | --- |
| 相同业务语义、结构与交互重复 | 优先共享组件；列出真实调用位置、差异与最小 props/slots/events |
| 仅颜色、间距、圆角、阴影重复 | 优先现有 Vuetify theme、CSS 变量或设计 token |
| 仅布局规则重复 | 评估布局组件或公共 utility；保留页面特有样式 |
| 可复用状态和行为重复 | 评估 composable，而不是带无关 UI 的大组件 |

- style 行数仅用于定位候选项。比较实际选择器、声明、模板结构和语义；不要把“长文件”当成缺陷。
- 检查 scoped、:deep、全局覆盖、选择器优先级、Vuetify 内部类依赖和响应式规则；提取后须考虑样式作用域及加载顺序。
- 对经常一起出现的 logo + 站名（例如 Moelian / 梦怜），全仓搜索图片、配置字段、文字和现有品牌组件。优先扩展已有组件，区分纯品牌展示和导航链接职责，避免嵌套链接。
- 复用建议必须给出至少两个具体使用点，说明哪些差异属于稳定变体，哪些应留给父组件。评估 props 膨胀和业务耦合；不要只凭视觉相似合并不同业务。
- 排查重复卡片、页头、空态、错误态、加载态、筛选和分页；仅报告实际存在且抽取收益明确的候选项。
- 抽取时核对多根节点的属性透传、class/style 合并、事件透传、v-model、slot、ref 和 scoped 样式依赖，防止外观相同但调用行为改变。检查自动导入组件名冲突。

## composable（hooks）

- 搜索重复的数据加载、分页筛选、路由同步、收藏/进度、断点、事件监听和偏好持久化；区分无状态工具函数、局部 composable 与跨页 Pinia 状态。
- 检查响应式输入、解构导致的响应性丢失、watch 重复触发、异步竞态、过期响应、卸载后副作用，以及事件/计时器/observer 的清理。
- 局部 ref 留在调用实例；共享 SSR 状态使用 useState 或 Pinia，避免模块顶层可变状态跨请求共享。useState key 和异步数据 key 必须与其状态归属一致。
- 建议抽取时列出输入、返回值、状态归属、生命周期和现有调用点；不要仅为缩短 setup 把任意代码搬进 useXxx。

## SSR 与水合

- 先建立路由渲染模式清单；已关闭 SSR 的页面也需检查客户端导航及它们引用的共享代码。
- 比较服务端 HTML 与客户端首次渲染：浏览器 API、localStorage、主题/登录态、断点、时间/时区/locale、随机数、ID、非法 HTML、嵌套交互元素及 Teleport。
- 浏览器能力放在合法客户端生命周期或分支中；检查服务端占位是否稳定。CSS 能解决的响应式展示优先考虑 CSS。
- 检查 useFetch/useAsyncData 的 key、响应式参数、共享选项、SSR payload、错误/空值处理与刷新行为；顶层 $fetch 是否引发服务端和客户端重复请求。用户操作请求可使用 $fetch。
- 检查自定义数据 composable 的 await 使用、Nuxt 上下文、认证信息透传、缓存中的用户隔离，以及 SSR 和客户端初始数据是否一致。
- 不以全站关闭 SSR、扩大 ClientOnly 或抑制 warning 作为默认修复；判断 SEO、首屏、布局跳动和交互延迟影响。
- 静态发现应描述为风险及触发条件；没有浏览器证据，不声称已经复现 hydration mismatch，也不声称“没有水合问题”。

## 交互与验证

- 核对加载、空数据、错误、刷新、直接访问及客户端导航；检查键盘、焦点、可访问名称、触摸和不同屏幕尺寸。
- 阅读器检查受影响的漫画单/双页、RTL、缩放、滚动、小说模式和进度恢复。主题或品牌修改检查浅色/深色及紧凑变体。
- 按仓库要求选择验证。报告实际执行的检查及结果；未运行给出原因。static-check 或 build 通过不能证明没有水合错误。
- 浏览器验证记录路由、视口、初始状态、操作、控制台警告和重复请求。环境缺失时明确待验证项，不编造运行结果。

## UI 重写的其他回归

仅检查改动涉及的分支；下列项目是审查线索，不是预先认定的缺陷。

- **路由与状态恢复**：旧链接、动态参数、query 筛选、分页、浏览器前进/后退、滚动位置、同一页面切换资源时的数据更新；检查 KeepAlive 缓存的过期状态及重复监听。
- **权限与用户隔离**：匿名、登录、会话过期和切换账号后的 UI、缓存与收藏/历史状态；隐藏按钮不能替代服务端鉴权。检查敏感字段是否进入 SSR HTML 或 payload，用户文本是否经 v-html 不安全渲染。
- **操作反馈**：提交中的重复点击、请求失败后的重试、乐观更新回滚、弹窗关闭后未完成请求，以及表单值/校验错误的保留。
- **可访问性细节**：弹窗焦点圈定与关闭后恢复、Escape、纯图标按钮名称、禁用态、非颜色提示，以及减少动画偏好。优先核对现有 Vuetify 能力是否被自定义实现破坏。
- **性能与布局**：长列表或漫画图片是否造成明显 DOM/内存增长；首屏图片与非首屏图片的加载策略、尺寸占位、重复挂载和大范围响应式更新。优化建议给出具体热点或测量证据，不默认引入虚拟列表、懒加载或新依赖。
- **公开页面 SEO**：页面标题、描述、canonical、分享元信息及无效资源的 HTTP 状态是否随路由正确更新；核对 UI 重写是否把原有首屏内容推迟到客户端加载。

## 输出契约

先报告会影响用户的缺陷，再独立列出可维护性建议：

1. **缺陷**：优先级、文件与精确行号、触发条件、可观察后果、证据和最小修复方向。只给可行动结论，区分本次引入与既有问题。
2. **复用建议**：重复位置、共同职责、推荐组件/composable/token、最小接口及抽取风险。纯重复不自动标为高优先级 bug。
3. **验证与边界**：比较基线、已覆盖区域、实际检查结果和未确认项。未发现缺陷时直接说明，并保留验证局限。

复用候选项给出建议执行顺序：先处理行为缺陷，再处理多处重复且接口稳定的抽取，最后考虑收益较小的样式整理。同一根因合并报告，避免为增加数量重复列问题。每个发现标明“代码可确认”“运行已复现”或“待验证风险”；附上适合该问题的验证方法。
