# 开发说明

## 开始开发

本项目采用 pnpm 进行依赖管理
开发: `pnpm run dev`

## AI 代码评审

PR 由 Open Code Review（`alibaba/open-code-review`）自动评审，LLM 使用 OpenCode Go 订阅（工作流：`.github/workflows/code-review.yml`）。

- **自动触发**：PR 打开（opened）、推送新提交（synchronize）、重新打开（reopened）时自动评审。
- **手动重跑**：在 PR 评论中以 `/open-code-review` 或 `@open-code-review` 开头发表评论即可重新评审（仅仓库成员可触发）。
- **评审结果**：由 `github-actions[bot]` 以行级评论 + 摘要评论形式回贴到 PR。
- **所需 secrets/variables**（Settings → Secrets and variables → Actions）：

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| Secret | `OCR_LLM_URL` | LLM 端点：`https://opencode.ai/zen/go/v1/chat/completions` |
| Secret | `OCR_LLM_AUTH_TOKEN` | OpenCode Go API key（Zen 控制台获取） |
| Variable | `OCR_LLM_MODEL` | 模型 ID，如 `deepseek-v4-pro` / `deepseek-v4-flash` |
| Variable | `OCR_LLM_USE_ANTHROPIC` | `false`（OpenAI 兼容端点） |

## 分支命名规范

分支命名必须以**版本号开头**，后接说明描述，格式：

`<版本号>-<描述>`

例如：

- `v1.2.0-fix-reader-bug`（v1.2.0 版本：修复阅读器问题）
- `v1.3.0-novel-search`（v1.3.0 版本：小说搜索功能）

规则说明：

- 版本号采用 semver 格式（`vX.Y.Z`），与目标发布 tag 对应
- 版本号与描述之间用单个短横线 `-` 连接
- 描述使用短横线 `-` 分隔单词（kebab-case），简要说明分支的工作内容
- 长期维护分支（`main`、`sit` 等）不受此规则约束

## 错误处理

本项目采用全局 200 响应，只要请求正确被业务处理函数接收，则统一返回 200 HTTP 状态码，具体业务状态由响应体中的 code 指示

- 当 code 为 0 时，请求成功
- 当 code 非 0 时，请求处理异常

新增业务异常只需要在 shared\errors.ts 中编写即可，服务端额外需要在 server\types\business_exception.ts 中导出对应异常
