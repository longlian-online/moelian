# 📚 在线阅读平台 (Online Reading Platform)

> 基于 Nuxt 4 构建的现代化漫画/小说在线阅读服务，提供沉浸式阅读体验和完善的内容管理系统

## 🎯 项目概述

这是一个功能完善的在线阅读平台，支持漫画和小说两种内容类型。项目采用现代化的全栈技术架构，实现了从内容上传、管理到用户阅读的完整业务流程。

## ✨ 核心功能

### 📱 前端功能特性

#### 🎨 响应式阅读界面

- **多设备适配**: 完美支持桌面端和移动端，提供针对性优化的阅读体验
- **智能阅读器**:
  - 漫画支持单页/双页切换、上下滚动/左右翻页模式
  - 小说提供舒适的文字阅读界面
  - 日漫模式支持（从右到左阅读）
- **沉浸式体验**: 全屏阅读、进度条控制、章节快速跳转

#### 🎯 用户交互优化

- **手势控制**: 支持触摸滑动翻页、双击缩放
- **键盘快捷键**: 方向键翻页、ESC退出等
- **个性化设置**: 阅读模式、主题切换、布局偏好保存
- **智能预加载**: 图片懒加载和预加载优化，减少等待时间

#### 💡 核心技术亮点

- **智能文件排序算法**: 自研 COS URL 解析和自然排序算法，支持 "1-2.jpg", "10.jpg" 等复杂文件名的正确排序
- **Canvas 动态封面生成**: 基于 Canvas API 的封面生成器，支持多色渐变文字、智能换行、圆角背景等高级绘制效果
- **复杂阅读器架构**:
  - 单页/双页自适应切换
  - 基于 IntersectionObserver 的精确进度跟踪
  - 支持日漫模式（RTL）的智能布局算法
- **全局状态管理模式**: 基于 Composition API 的全局确认对话框系统，实现组件间解耦通信
- **主题系统设计**: 8种预设主题的动态切换系统，支持实时颜色计算和持久化存储
- **云存储直传架构**: 预签名 URL + 客户端直传，减轻服务器压力，支持上传进度和取消控制

### 🔧 管理后台

- **内容管理**: 作品创建、章节上传、状态控制
- **用户管理**: 用户权限控制、账户状态管理
- **资源管理**: 文件上传、存储管理、资源清理

### 🌐 后端服务架构

- **RESTful API**: 标准化接口设计，支持前后端分离
- **身份认证**: JWT + Session 混合认证机制
- **文件处理**: 支持漫画压缩包解压、小说文档解析
- **云存储集成**: 腾讯云 COS 直传，减轻服务器压力
- **消息队列**: NATS 异步任务处理
- **定时任务**: 资源清理、数据同步等后台任务

## 🚀 技术栈

### 前端技术

- **框架**: Nuxt 4 (Vue 3 + Server-Side Rendering)
- **开发语言**: TypeScript
- **UI 框架**: Vuetify 3 (Material Design)
- **状态管理**: Pinia
- **构建工具**: Vite + ESBuild
- **代码规范**: ESLint + Prettier
- **测试框架**: Vitest + @nuxt/test-utils

### 后端技术

- **运行时**: Node.js 20.19.5
- **服务端**: Nitro (Nuxt Server Engine)
- **数据库**: PostgreSQL + Prisma ORM
- **身份认证**: nuxt-auth-utils
- **云存储**: 腾讯云 COS
- **消息队列**: NATS JetStream
- **日志系统**: Winston

### 开发工具

- **包管理**: pnpm
- **版本控制**: Git
- **部署**: Docker + 云服务器
- **CI/CD**: GitHub Actions

## 🎯 核心业务流程

### 📖 阅读流程

1. 用户浏览作品列表，选择感兴趣的内容
2. 进入作品详情页，查看简介和章节列表
3. 选择章节开始阅读，系统自动适配设备类型
4. 阅读过程中支持实时设置调整和进度保存
5. 章节间无缝切换，提供连续阅读体验

### 📁 内容管理流程

1. 管理员上传作品资源（压缩包/文档）
2. 系统自动解析和处理内容文件
3. 资源上传至云存储，生成访问链接
4. 内容审核通过后发布给用户
5. 定时任务清理过期和无效资源

## 🔧 安装与运行

```bash
# 克隆项目
git clone [项目地址]

# 安装依赖
pnpm install

# 生成数据库类型定义
npx prisma generate

# 启动开发服务器
pnpm dev

# 构建生产版本
pnpm build
```

## 🤝 贡献与分支保护

贡献代码前请阅读 [CONTRIBUTING.md](CONTRIBUTING.md)。提交 Pull Request 到 `main` 时，GitHub Actions 会自动执行静态检查、测试和构建。

请在 GitHub 仓库设置中启用以下分支规则：

- `main`：禁止直接 push，只能通过 Pull Request 合并；要求 `Pull Request Validation / validate` 检查通过，并将允许合并者限制为仓库管理员或指定维护者团队。
- `sit`：不要求 Pull Request 验证，但禁止非管理员直接 push，仅允许管理员维护该分支。
